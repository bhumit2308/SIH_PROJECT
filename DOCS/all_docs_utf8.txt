========== 01_Project_Brief.docx ==========
01. Project Brief
Project: AI-Assisted Legal Metrology Compliance & Inspection System | SIH Problem Statement: SIH26034
Document purpose: Clear, implementation-ready guidance for the METRA SIH team. Language is intentionally simple; technical terms are explained where needed.
1. Project Overview
METRA helps inspectors check packaged commodities by scanning package images, extracting declarations with OCR/vision, applying the correct versioned compliance rules, linking findings to image evidence, routing uncertain cases to a human reviewer, and generating audit-ready reports.
2. Problem
Legal Metrology officers may need to inspect packaged products for mandatory declarations. Manual checking takes time, can be inconsistent, and makes large-scale inspection difficult.
3. Goal
Reduce repetitive inspection work.
Make checks consistent and explainable.
Keep image evidence with every finding.
Support human officers instead of replacing them.
Produce an audit-ready inspection record.
4. Core Idea
Package images ΓåÆ Quality check ΓåÆ OCR/Vision ΓåÆ Structured declarations ΓåÆ Applicable rule pack ΓåÆ Compliance checks ΓåÆ Evidence ΓåÆ Human review ΓåÆ Report/Dashboard
5. Product Modes
Mode
Purpose
Inspector Mode
For official inspection and review workflows.
Compliance Pre-Screening
For manufacturers/packers/importers to find potential issues before release. It is not legal approval.
6. MVP Scope
Start with selected packaged consumer-product categories, not every category.
Support multi-image capture (front/back/side).
Extract core declarations such as name, manufacturer/packer/importer, net quantity, MRP, relevant date information, consumer-care details, and country of origin where applicable.
Run versioned rule checks.
Show evidence and confidence.
Route uncertain cases to a human reviewer.
Generate a report.
7. Non-Goals
Do not claim 100% automated legal decisions.
Do not claim physical measurements can always be derived from a normal photo.
Do not build dozens of product categories in the first release.

Department of Consumer Affairs ΓÇö Legal Metrology overview: https://consumeraffairs.gov.in/pages/legal-metrology-overview

No readable text ΓåÆ request new image.
Conflicting fields across images ΓåÆ flag conflict.
Rule unavailable ΓåÆ do not guess; mark ΓÇ£rule not configuredΓÇ¥.

12. Business Rules
Project: AI-Assisted Legal Metrology Compliance & Inspection System | SIH Problem Statement: SIH26034
Document purpose: Clear, implementation-ready guidance for the METRA SIH team. Language is intentionally simple; technical terms are explained where needed.
1. Core Principle
METRA is an assistance system. It should never present an uncertain AI output as a confirmed legal decision.
2. Rules
ID
Rule
BR-01
Every inspection must have at least one package image.
BR-02
An image that fails quality checks cannot be treated as reliable evidence.
BR-03
Required declarations come from the selected rule pack/category context.
BR-04
AI/OCR output is a candidate value; final validation is performed by deterministic rules.
BR-05
Every warning/violation should have evidence or a clear explanation when evidence is unavailable.
BR-06
Low-confidence or conflicting findings require human review.
BR-07
Physical measurements that cannot be inferred reliably from the image require manual verification.
BR-08
A finalized inspection records the rule-pack version used.
BR-09
Published rule packs cannot be silently edited; create a new version.
BR-10
Human reviewer decision is the final workflow outcome for reviewed findings.
BR-11
Pre-screening results must be labeled as potential issues, not legal approval.
BR-12
If the system cannot determine an applicable rule, it must flag the rule gap rather than guess.

Overall status should be derived from findings. Example: any confirmed critical violation ΓåÆ NON-COMPLIANT; unresolved uncertainty ΓåÆ REVIEW REQUIRED; no violations and all required checks passed ΓåÆ COMPLIANT.

Project: AI-Assisted Legal Metrology Compliance & Inspection System | SIH Problem Statement: SIH26034
Document purpose: Clear, implementation-ready guidance for the METRA SIH team. Language is intentionally simple; technical terms are explained where needed.
1. Security Goals
Protect package images and inspection records.
Prevent unauthorized access to reports and evidence.
Protect admin rule management.
Keep audit records trustworthy.
2. Controls
Area
Control

3. Privacy Principles
Collect only information needed for inspection and account management.
Define retention periods for images and reports.
Allow authorized deletion/retention handling according to organizational policy.
Do not send more image data to an AI provider than needed.
4. Threats to Test
Broken access control.
Malicious file upload.
Prompt injection through packaging text.
AI provider outage.
Rule tampering.
Report URL leakage.
Audit-log deletion/modification.

Treat all package text as untrusted data. It must never be interpreted as system instructions. The AI adapter should receive a constrained extraction task and return structured output that is validated server-side.

The one-sentence product definition
METRA is a web platform that helps inspectors analyze package images, extract declarations, apply the correct rule pack, show evidence-backed findings, route uncertain cases to human review, and create an auditable inspection record.
The non-negotiable product boundary
METRA is inspection assistance and decision support, not an autonomous legal authority; regulatory rules stay in versioned rule packs and must not be hidden inside prompts.
AI extracts and interprets information; the deterministic rule engine decides the configured compliance result.
If an image cannot reliably prove a physical or measurement requirement, METRA must request manual verification instead of guessing.

Allow human reviewers to accept, correct or reject AI-assisted findings.
Produce a reproducible inspection report and audit trail.
Create an architecture that can later expand to more product categories and rule packs.
Non-goals for the SIH MVP
All Indian product categories and all possible legal exceptions.
Autonomous legal enforcement or automatic fines.
Perfect physical font-size measurement from arbitrary photographs.

20+ language optimization.
Government-scale multi-region infrastructure.

5. Product Workflow and Functional Specification
A. Create inspection
Choose or confirm category/context.
Create inspection draft.
Allow optional product name, notes and source information.
Bind the inspection to the rule-pack version used for evaluation.
B. Image capture and quality gate
Accept JPEG/PNG/WebP within configured size limits.
Normalize orientation and relevant metadata.
Run basic checks for size, blur, extreme darkness/brightness and likely unreadability.
Allow recapture before invoking expensive AI calls.
C. AI/Vision extraction
Extract only defined fields from a strict schema.
Store value + confidence + source image + optional bounding region.
Preserve original OCR text when needed for audit/debugging.
Keep the provider behind a replaceable interface.
D. Category + rule resolution
Resolve the applicable rule pack based on selected/identified context.
Pin the exact rule-pack version to the inspection.
Do not let the LLM invent legal rules.
If applicability is uncertain, mark the case for review.
E. Deterministic validation
Check type
Example behavior
Presence
Required declaration exists / missing
Structure
Value follows configured structure or pattern
Value/quantity
Configured validation of normalized quantity/value
Consistency
Conflicting values across package images
Placement/readability
Potential issue detected; manual verification when proof is insufficient
Applicability
Rule only runs where the rule pack says it applies
F. Finding + evidence
Every important finding gets status, severity, message, confidence and rule reference.
Evidence stores image, region/bounding box where available, and source value.
Do not overwrite original AI finding when a reviewer corrects it; store review action separately.
G. Human review
Accept finding.
Correct finding.
Reject finding.
Add reviewer note when needed.
Lock final decision when inspection is finalized.
H. Report + audit
Generate structured report with inspection metadata, findings, evidence references, rule version and reviewer action.
Store immutable audit events for key transitions.
History screen must allow authorized users to reopen finalized inspection details without changing the record.

11. AI/OCR Product Contract
What AI is allowed to do
Read package text and visual context.
Propose structured field values.
Return confidence and source regions where possible.
Flag ambiguity.
Assist category/context suggestion.
What AI is NOT allowed to do
Invent legal requirements.
Write or change rule-pack logic.
Finalize a legal inspection without rule evaluation and human workflow.
Claim physical measurements that cannot be supported by capture/calibration.
Return free-form prose as the only machine-consumed output.
Strict extraction contract
The model should return structured JSON matching a schema. Unknown values should be null/unknown rather than guessed. Each field should include source image and confidence metadata when available.
Provider adapter interface
Conceptual contract: analyze_images(images, extraction_schema) ΓåÆ ExtractionResult. Keep Gemini behind the adapter so another provider can be substituted later.
